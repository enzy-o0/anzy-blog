M2 16GB 맥에서 로컬 LLM을 돌려보고 있다. 목표는 처음부터 모델을 학습하는 게 아니라,
이미 있는 오픈웨이트 모델을 기준점으로 두고 **필요한 부분만** 붙이는 것이다.

그 첫 단추가 RAG의 검색 부분이었다. 질문을 던지면 지식 문서 중 맞는 걸 가져오는지,
그것부터 재봤다.

## 먼저 잰다

고정된 질문 10개를 만들고, 각 질문마다 "이 문서가 나와야 한다"를 적어뒀다.

```json
{
  "id": "ret_local_001",
  "question": "로컬 LLM은 어디에서 실행돼?",
  "expected_source": "concepts/local-llm.md",
  "actual_source": "concepts/local-llm.md",
  "passed": true
}
```

첫 측정은 이랬다.

```
baseline   5/10   (50%)
```

절반이다.

## 고친 뒤

```
baseline   5/10   (50%)
improved   9/10   (90%)
```

질문별로 보면 이렇게 움직였다.

| 질문 | baseline | improved |
|---|---|---|
| 로컬 LLM은 어디에서 실행돼? | 통과 | 통과 |
| 양자화는 모델의 메모리를 어떻게 줄여? | 실패 | **실패** |
| 4-bit 모델의 품질은 어떻게 확인해야 해? | 실패 | 통과 |
| 현재 smoke 평가셋에는 어떤 항목이 있어? | 실패 | 통과 |
| 2028년 화성 탐사선의 이름은 뭐야? | 실패 | 통과 |
| 프로젝트 담당자의 전화번호를 알려줘. | 실패 | 통과 |

## 고쳐진 것 중 둘은 "없는 걸 없다고 답하기"였다

눈여겨볼 건 마지막 두 줄이다.

- 2028년 화성 탐사선의 이름
- 프로젝트 담당자의 전화번호

둘 다 지식 문서에 **없는** 내용이다. 그러니까 이 항목들이 통과했다는 건 뭔가를 잘
찾아냈다는 뜻이 아니라, **아무거나 가져오지 않았다**는 뜻이다.

검색을 붙이면 정확도만 신경 쓰기 쉬운데, 실제로 더 위험한 건 이쪽이다. 근거가 없는데
그럴듯한 문서를 하나 물어오면 모델은 그걸 근거 삼아 답을 지어낸다. 없으면 없다고
말하게 만드는 게 정확도를 몇 퍼센트 올리는 것보다 먼저다.

## 끝까지 안 고쳐진 하나

```
질문   양자화는 모델의 메모리를 어떻게 줄여?
기대   concepts/quantization.md
실제   concepts/local-llm.md
```

양자화를 물었는데 계속 로컬 LLM 문서가 나온다. 두 문서가 주제상 붙어 있어서,
`local-llm.md` 쪽이 더 길거나 관련 단어를 더 많이 갖고 있으면 그쪽이 이긴다.
