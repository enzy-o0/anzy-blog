# 새 포스트 추가

`content/posts/<slug>.md` 파일 하나를 만들면 끝난다. 목록과 라우트는 파일시스템에서 따라온다.
`app/` 아래 코드는 건드리지 않는다. 건드려야 한다면 뭔가 잘못된 것이다.

## 0. 스크립트로 뼈대부터

```bash
npm run new-post -- my-slug "글 제목"
```

슬러그 형식을 검사하고, 오늘 날짜와 필수 필드가 채워진 `draft: true` 파일을 만든다.
이미 있는 파일은 덮어쓰지 않는다. 아래 1~2단계는 이 스크립트가 대신 해 주므로,
직접 만들 때나 규칙을 확인할 때만 읽으면 된다.

## 1. slug 정하기

파일 이름이 곧 URL이다. `content/posts/foo.md` → `/posts/foo`

- 영문 소문자, 숫자, 하이픈만 사용한다 (한글·공백·대문자 금지)
- 이미 있는 slug인지 `content/posts/`를 먼저 확인한다
- frontmatter에 `slug` 필드를 넣지 않는다. 파일 이름이 진실이다

## 2. frontmatter 작성

`lib/schema.ts`가 요구하는 형태다. **스키마를 먼저 읽고** 그때의 정의를 따른다.
아래는 작성 시점의 모습이며, 스키마가 바뀌었다면 스키마가 맞다.

```yaml
---
title: 글 제목            # 필수, 비어 있으면 안 됨
description: 한 줄 요약    # 필수, 목록과 <meta description>에 쓰인다
date: "2026-08-12"        # 필수, YYYY-MM-DD, 따옴표를 반드시 붙인다
categories: [NextJS]      # 선택, 기본 []
tags: [nextjs, react]     # 선택, 기본 []
author: Anzy              # 선택, 기본 "Anzy"
draft: true               # 선택, true면 목록에서 제외된다
---
```

`date`에 따옴표를 붙이는 이유: YAML이 따옴표 없는 `2026-08-12`를 `Date` 객체로 자동 변환한다.
스키마가 정규화해 주긴 하지만, 원문에서 의도를 분명히 해 두는 편이 낫다.

초안 단계면 `draft: true`로 시작한다. 목록에서 빠질 뿐 파일은 그대로 있다.

## 3. 본문 작성

**코드펜스에는 반드시 언어를 적는다.**

````
```tsx
const x = 1;
```
````

자동 언어 감지는 꺼져 있다(`lib/markdown.ts`). 언어를 빠뜨리면 색이 입혀지지 않는다.
빌드는 통과하므로 조용히 넘어간다 — 그래서 여기서 챙겨야 한다.

기타:
- GFM을 쓸 수 있다 (표, 취소선, 태스크 리스트)
- 마크다운 안의 raw HTML은 파이프라인에서 제거되므로 쓰지 않는다
- 이미지는 `public/`에 두고 `![alt](/파일명.png)`로 참조한다

## 4. 확인

```bash
npm run verify
```

frontmatter가 스키마를 어기면 **빌드가 실패하고** 어느 파일의 어느 필드가 왜 틀렸는지 출력된다.
그 메시지를 읽고 고친다. 검증을 우회하거나 스키마를 느슨하게 바꿔서 통과시키지 않는다.

빌드 로그에 새 글이 `● /posts/<slug>` 로 잡혔는지 확인한다. `draft: true`면 상세 페이지는
생성되지만 목록에는 나오지 않는다.

## 5. 커밋

`CLAUDE.md`의 커밋 규칙을 따른다. 글 추가는 보통 이런 형태다.

```
docs: <글 제목> 발행
```
